# 设计取舍

## 题库不进仓库

题目来自校内复习手册与划重点页，属于原始资料的版权方。把题目打进构建产物等于随代码公开发布，所以：

- `src/` 里没有任何题目字面量，构建产出 `dist/` 干净；
- 应用启动时从本机文件导入题库，存 `localStorage`，键名 `killquestion.bank.v1`；
- `input/`（PDF 与全文）与 `data/`（解析中间产物）都在 `.gitignore`。

代价是首次使用多一步导入，换来的是仓库可以公开、网站托管在 Pages 上也不涉及分发题目。

## 为什么不用 IndexedDB

起点项目（错笺）用 Dexie 七张表存题目。这里题库是**只读**的、由用户导入，进度只有「每题对几次错几次」，总量几百 KB 量级，`localStorage` 足够而且同步读写更简单。

数据结构：

```ts
{ records: { [questionId]: { right, wrong, lastAt } }, stars: [], session: {...}, finishedSessions, lastStudyAt }
```

## 判分口径

- 选择题按**选项字母集合**比对，不看顺序；空选、漏选、多选都算错。
- 判断题只有两个按钮，答案里的 √ × 对 错 T F 先归一化成「正确 / 错误」再比；
  原题没给答案（答案读不出来）的判断题退回自评，而不是直接判错。
- 填空先归一化（NFKC → 去零宽 → 去空白 → 小写 → 去标点）再逐空比对。宁可严格一点让人自己判断，也不要放过「差不多就对」。
- 简答/论述：先打字作答，交卷后按要点对照自动判（详见下一节）；如果题库没有参考答案、或者一个字都没写，就退回「看答案 + 自评」，而不是硬判错。

## 选项每次出题都打乱

背题靠的是「知道哪个说法对」，不是「记住选 C」。所以每道选择题上桌时：

- 选项顺序按 Fisher–Yates 重排，字母**按显示位置重新编 A、B、C…**（`optionLetters`）；
- 答案同步换成新字母——`shuffleChoiceOptions` 一次返回配套的 `options + answer`，调用方不许自己拼，
  否则就会出现「选项写着 A 却在第三个位置」或者「判分还按旧字母比」的错判；
- 所以 `store` 里的 `current` 是**上桌副本**（`presentQuestion`），题库索引里的原题一个字不动：
  背题稿、题库页、导出 JSON 仍是原顺序原字母；
- 位置相关选项（「以上都对 / 上述均不正确」）整题锁定原顺序，换位置题目就自相矛盾了（`hasPositionalOption`）；
- 每次 `loadCurrent`（下一题、重开一轮、刷新后续上）重新洗，种子取时间 + 随机，所以同一题连刷两次顺序也不同；
- 判分仍走 `gradeChoice`，只是比的是上桌字母，等价性由 `src/core/shuffle.test.ts` 与 `src/store/quiz.test.ts` 守住。


## 简答 / 论述：打字作答 + 要点对照

这两类题没有唯一答案，所以既不假装能判准、也不让人只能空着手自评，做法是「给一个参照分 + 允许推翻」：

- **拆要点**（`splitAnswerPoints`）：先按「（一）」「①」「行首 1.」这类标记分段，段内按 `。；！？` 拆句；超过 28 字的句子再按逗号/顿号切（28 是拿真实题库试出来的，再低就把「坚持人民民主专政」这类正常要点拆碎）。短于 6 字的残句并进上一句。真实题库 43 道简答/论述，拆完 5 道仍是 1 条、其余 2—20 条。
- **算覆盖**（`keyGrams` + `gradeEssayAnswer`）：答案要点与用户输入都取中文 bigram（拉丁/数字同样滑窗），两个字都是虚字（「的是」「和的」）的片段丢掉。每条要点的命中率 ≥ 60% 算「答到」，汇总分按 bigram 数加权，**≥ 55% 判对**。
- **页面**：给出「匹配度 X% · 答到 m/t 条要点」，下面是逐条对照（✓ 答到 / ○ 没答到），交卷后输入框锁住。
- **可推翻**：判得不对点「算我答错 / 算我答对」，`reviseEssay` 先把上一次记的分回滚再记新的（同一道题不会记两遍），页面上标「已按你的判断改判」。
- **已知局限**：这是词面匹配，同义改写（「工人阶级」↔「无产阶级」）算不中，重复关键词也刷不到分（按集合算）。所以页面上写明「词面对照仅供参考」，判定永远可以人工覆盖。
- 没写东西（少于 2 个字）或题库没给参考答案时不自动判分，原样退回自评流程。

## 考点是可选的维度

`topicIds` 为空数组的题不算重点题。重点刷题只抽 `topicIds` 非空的题，按考点刷只抽某考点覆盖的题。这样「划重点」和「整库」是同一份数据，不用维护两个题库。

## 会话持久化

正在进行的练习会存进 `localStorage`，刷新、关页面、换 tab 都能接着刷。`session.index` 指向队首，`results` 只追加。

## 让题库能被校验

`validateBank()` 在写入前检查 `id` 唯一、`type` 合法、`stem` 非空。导入半截数据比导入失败更难排查。
