# KillQuestion

本地优先的题库刷题应用。**重点刷题**和**大范围刷题**两条主线，填空 / 单选 / 多选 / 判断 / 简答 / 论述六种题型都能刷，**PDF / Word 题库直接拖进来解析**，另有**背题稿**把整份题库摊成一页文字，数据只存在你自己的浏览器里，断网也能用。

在线版：<https://zmfk.github.io/KillQuestion/>

---

## 题库从哪来：把 PDF / Word 直接拖进去

这个仓库**只放程序，不放任何题目内容**。题目属于原始资料的版权方（复习手册与划重点页），不适合随代码公开分发，所以题库不打包进构建产物，`dist/` 里一行题目都没有。

打开应用进「导入」页，把文件拖进去就行，**解析在你自己浏览器里跑，不上传任何服务器**：

| 拖进去的文件 | 会被当成 |
| --- | --- |
| 题库 PDF / Word（`.docx`） | 题库：按「填空题 / 选择题 / 判断题 / 简答题 / 论述题」这类小节切开（序号不固定，按题型名认），答案认「答：」和「正确答案：」 |
| 划重点 PDF / Word | 考点清单：按「一、二、…」分组、一行一条考点 |
| 题库 JSON（含 `questions`） | 题库，直接可用 |
| 考点 JSON（含 `topics`） | 考点清单 |

- 一次可以选多个：**题库 + 划重点一起拖**，解析完立刻把考点挂到题上，「重点刷题」就有范围了；
- 只有题库也能用，只是「重点刷题」暂时没数据；
- 已经有题库了，再拖一份划重点就是**只重新标注**，题目和作答记录都不动；
- 解析完先给你看预览（多少题、题型分布、多少考点、多少重点题），确认了才写进本机浏览器（`localStorage`）。

想拿到一份可备份的文件，点「导出成 JSON」，结构见下文「题库格式」。换浏览器、换设备、清缓存都要重新导入一次，学习记录也会一起丢。

读不出来的常见情况：**扫描版 PDF**（整页是图片、鼠标选不中文字）——先用 OCR 转成文字版；旧版 `.doc`——先在 Word/WPS 里另存为 `.docx`。

### 实在读不出来：让 AI 转成 JSON

碰到扫描件、双栏乱序、表格排版的书，内置解析会失手。这时换个思路——**让大模型按固定格式把资料整理成 JSON**，再粘回来导入，结果一样只存在你自己这台设备上：

1. 进「导入」页，展开 **「读不出来 / 想更稳？用 AI 把资料转成 JSON」**；
2. 复制里面那段提示词，打开任意大模型（DeepSeek、Kimi、通义、ChatGPT、Claude 都行），把提示词和资料一起贴进去；
3. 它吐出 JSON 后整段复制，粘到下面 **「AI 转出来的 JSON / 已有题库 JSON，粘在这里」** 的框里，点导入；
4. 先看预览的题数、题型分布、考点数，对得上再写入本机。

提示词已经写死了输出格式（题型、选项、答案、考点、`id` 编号规则），也明确要求「照抄原文、缺答案就留空、不要自己编」。但大模型仍可能漏题或补答案，**导入前务必核对总题数**；资料上百页要分段喂，一次一两个小节。

## 两种用法

### 1. 在线版（推荐）

打开 <https://zmfk.github.io/KillQuestion/> → 把题库 PDF / Word 拖进「导入」→ 开始刷。

手机上还可以「添加到主屏幕 / 安装应用」，装完就是个离线 App。

### 2. 本地版（自带服务，不联网也能开）

需要 Node.js 18+。双击根目录的 **`启动.cmd`**：它会自动找 Node、缺依赖就装、没构建就先构建、然后起本地服务并打开浏览器。关掉那个黑窗口就停止服务。

不想装环境就直接用在线版，功能完全一样。

## 刷题方式

| 入口 | 说明 |
| --- | --- |
| **重点刷题** | 只刷被划重点覆盖的题，考前冲刺 |
| **大范围刷题** | 全库随机，不留死角 |
| **未完成 · 全量 / 重点** | 只出还没答过的题（首页两个按钮），做过一次就算完成，用来把整库刷干净 |
| **顺序通刷** | 按原书顺序（填空→选择→判断→简答→论述）从头过 |
| **模拟考试** | 按真实卷面配比组卷，60 分钟倒计时，到点自动交卷 |
| **错题重刷** | 只抽「错得比对得多」的题（做错但还没订正的，和「未完成」不重叠） |
| **收藏夹** | 做题时点星标收起来 |
| **按考点刷** | 划重点页拆成的考点，一个一个打 |

判分规则：

- **单选 / 多选**：按选项集合比对，多选漏选算错；选项每次出题都重排、字母按位置重编，答案跟着换字母；
- **判断**：只有「正确 / 错误」两个按钮；答案里的 √ × 对 错 T F 一律归一化成「正确 / 错误」再比，原题没给答案的退回自评；
- **填空**：全角半角、空白、标点、大小写一律归一化后逐空比对，少一个空算错；
- **简答 / 论述**：先打字作答，交卷后按要点对照判分（匹配度 ≥55% 判对，逐条给 ✓/○），判得不对可以自己改判；没写东西或题库没答案时退回自评。

## 背题：整份题库摊在一页上

「背题」页（`/#/recite`）不是做题，是**把题库原文摊平了直接读**：考点清单在前，题目按 填空 → 选择 → 判断 → 简答 → 论述 排在后面，每道题的题干、选项、答案全部印出来，一个字都不改写。

页面上的开关和按钮：

| 开关 | 作用 |
| --- | --- |
| **遮住答案** | 答案行换成「先自己回想」，先自测再翻开 |
| **只看重点** | 只留划重点覆盖的题，考前最后一遍 |
| **带考点清单** | 关掉就只剩题目，页面更短 |
| **打印 / 存 PDF** | 走浏览器打印，导航与按钮自动隐藏，正文黑字白底 |
| **复制全文 / 下载 .txt** | 同一份内容导出成纯文本，丢进手机备忘录也行 |

一篇 300 题左右的题库摊出来大概 6 万像素高，全量一次渲染——这是故意的，要的就是「从头滚到尾」的连续感，而不是分页。

## 备份与恢复：把答题记录搬到别的设备

所有数据都只存在**当前这台设备的浏览器**里（`localStorage`），换设备、换浏览器、清缓存都会丢。所以导入页（`/#/import`）底部有一块「备份与恢复」：

| 操作 | 说明 |
| --- | --- |
| **导出备份** | 一个 JSON 文件，含答题记录、错题、收藏、完成轮次、没刷完的那一轮；勾选「连题库一起打包」时题库也一起带走（约 200 KB） |
| **导入备份** | 拖进来或选文件。选**合并**：同一题的次数相加、收藏取并集（适合两台设备都有进度）；选**覆盖**：完全以备份为准（适合从旧手机搬到新手机） |
| **只导答题情况** | 取消勾选题库，只搬记录（约几 KB）。到新设备先导题库、再导这份也能对上 |

导出的文件名形如 `KillQuestion-备份-20261102-0845.json`，文件不经过任何服务器。备份里题库是明文——**发给别人等于把题目也发出去了**。

## 题库格式

下面是「导出成 JSON」得到的结构（也是可以直接拖回来导入的格式）。示例里的题干、答案都是编的占位文字。

```jsonc
{
  "version": 1,
  "meta": { "title": "题库名", "total": 3, "counters": {}, "keyTotal": 1 },
  "topics": [
    { "id": "k01", "section": "一、示例分组", "title": "示例考点", "count": 1 }
  ],
  "questions": [
    {
      "id": "Q0001",
      "type": "fill",              // single | multi | judge | fill | short | essay
      "no": 1,
      "section": "fill",
      "sectionLabel": "填空题",
      "stem": "示例题干，（ ）表示一个空位。",
      "answer": ["示例答案"],
      "answerText": "示例答案",
      "blanks": 1,
      "topicIds": ["k01"]          // 属于哪些考点，可为空数组
    },
    {
      "id": "Q0002",
      "type": "single",
      "stem": "示例选择题题干。",
      "options": [{ "key": "A", "text": "示例选项" }],
      "answer": ["A"],
      "topicIds": []
    },
    {
      "id": "Q0003",
      "type": "judge",             // 判断题：答案只填「正确」或「错误」
      "no": 1,
      "section": "judge",
      "sectionLabel": "判断题",
      "stem": "示例判断题的一句话表述。",
      "answer": ["错误"],
      "answerText": "错误",
      "topicIds": ["k01"]
    }
  ]
}
```

导入时会校验：`id` 唯一、`type` 合法、`stem` 非空；判断题的答案会被统一成「正确 / 错误」。结构不对会直接报错，不会写半截数据。

## 开发

```bash
npm install
npm run dev        # 开发服务器
npm run typecheck  # 类型检查
npm test           # 单元测试
npm run build      # 生产构建（产物在 dist/）
npm run verify     # typecheck + test + build + 发布守卫，一条命令过全套
```

### 发布守卫

`npm run check:release`（CI 与 Pages 工作流都会跑）负责守住「仓库和产物里没有原始资料与题目」：

- 进仓库的文件里不能有 PDF / Office 原件（按扩展名 + 文件头魔数双重判断，改个名字也拦得住）；
- 进仓库的 JSON 只允许 `package.json` / `package-lock.json` / `tsconfig.json` / `manifest.webmanifest`；
- `dist/` 里的文件必须在白名单内，且不能出现题库的 JSON 数据结构。

判据用的是「结构」而不是「某几道题的文字」——把题干写进检查脚本，等于又把题目塞回仓库。

部署：推送到 `main` 后 `.github/workflows/pages.yml` 会跑测试、构建并发布到 GitHub Pages。构建用 `base: './'` + `HashRouter`，所以子路径下刷新不会 404。

### 解析这一层是怎么做的

应用里没有任何后端，解析全在浏览器：

- **PDF**：`pdfjs-dist`（worker 按需加载，第一次拖 PDF 才下载），逐页取文本；从 pdfjs 拷来的 CMap 表放在 `dist/cmaps/`，给那些没内嵌 ToUnicode 的中文 PDF 兜底映射。
- **Word**：`.docx` 本质是 zip，用 `fflate` 解出 `word/document.xml`，按段落取 `<w:t>` 文本。
- **切题**：`src/core/parseBank.ts` 与当初的 `scripts/parse_bank.py` 同一套规则（答案行作锚点切块、选项粘连修复、页眉页脚过滤），跑过 159 页原书，312 题分布与 Python 版逐题型一致；小节标题按题型名认（「判断题」放在第几节都能认出来）。
- **挂考点**：`src/core/matchTopics.ts` 从考点标题自动派生关键词（去套话 → 切词 → 剥类名词尾 → 取 5 字以内的连续片段），再用「这个词在题库里出现得有多频繁」来分档：满库都有的词（「中国共产」「历史意义」）不算数，只在少数题里出现的词才算强信号。**选项里只算正确答案那几项**——干扰项常塞着别的考点的专名词，算进去就会把题错挂到那个考点上。
- 自动标注会比人工整理的关键词表严格一些（宁可少标也不乱标），预览页会把「重点题 / 总题数」和识别到的问题直接列出来。

### 命令行批量重建（可选）

浏览器里能做的事，命令行也能做，适合一次处理很多份资料：

```bash
python scripts/parse_bank.py        # input/bank_raw.txt  → data/bank.json
python scripts/match_keypoints.py   # 匹配考点           → data/bank_tagged.json
python scripts/build_app_data.py    #                    → KillQuestion-题库.json
```

`input/`（PDF 与提取的纯文本）和 `data/`（中间产物）都在 `.gitignore` 里，不会进仓库。

